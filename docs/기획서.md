## 2. 기획 의도와 게임 목적

「라스트 존」은 좀비에게 둘러싸인 생존자가 제한된 공간에서 이동하고 사격하며 살아남는 게임이다. 플레이어는 좀비의 접근 방향을 파악하고, 안전한 위치로 이동하면서 마우스로 조준하여 적을 처치한다. 최종 목표는 체력이 소진되기 전에 총 3개의 웨이브를 모두 클리어하는 것이다.

이동과 조준을 동시에 수행하는 직접적인 조작 재미를 중심으로 설계한다. 일반 좀비로 기본 조작을 익힌 뒤, 빠른 좀비와 튼튼한 좀비를 순서대로 추가하여 회피와 공격 대상 선택의 중요성을 높인다. 맵을 여러 개 제작하는 대신 하나의 전투 공간 안에서 적 구성과 등장 간격을 변화시켜 콘텐츠를 확장한다.

C++과 glc2d를 활용하여 실시간 입력, 객체 이동, 충돌 판정, 시간 기반 적 생성, 애니메이션, 게임 상태 전환을 구현하는 것을 학습 목표로 한다.

## 3. 배경 및 화면 구성

좀비 사태 이후 폐쇄된 도시의 마지막 안전 구역이 무너졌다. 플레이어는 폐허가 된 구역에 홀로 남은 생존자로, 사방에서 접근하는 좀비를 물리쳐야 한다.

- 시점: 위에서 내려다보는 2D 탑다운 시점.
- 맵: 한 화면 안에서 플레이하는 고정 경기장 1개.
- 목표 해상도: 1280 × 720. 실제 출력 크기는 수업용 기본 프로젝트에 맞춰 조정한다.
- 전투 공간: 가장자리의 생성 지점을 제외한 중앙 공간에서 이동과 사격을 수행한다.
- 화면 상단: 플레이어 체력, 현재 웨이브, 남은 적 수 표시.
- 화면 중앙: 플레이어, 좀비, 총알, 발사·피격 효과 표시.
- 시각 구분: 플레이어와 좀비, 총알이 배경에 묻히지 않도록 색과 윤곽을 구분한다.

## 4. 조작 방법

| 입력 | 기능 |
|---|---|
| W / A / S / D | 위 / 왼쪽 / 아래 / 오른쪽 이동 |

대각선 이동은 방향 벡터를 정규화하여 상하좌우 이동과 속도를 동일하게 유지한다. 플레이어의 이동 범위는 화면 안으로 제한한다. 일시정지 중에는 적 이동, 총알 이동, 적 생성 및 웨이브 대기 시간이 함께 정지한다.

## 5. 핵심 게임 규칙

### 5.1 플레이어

- 초기 체력은 5이며, 좀비와 접촉하면 체력이 1 감소한다.
- 피격 후 1초 동안 무적 상태가 되어, 접촉 상태에서 체력이 즉시 모두 소진되는 것을 방지한다.
- 피격 시 캐릭터를 깜빡이게 하여 피해와 무적 상태를 표시한다.
- 무기는 권총 1종이며, 초기 설계에서는 탄약 수와 재장전을 두지 않는다.
- 발사 간격은 0.25초, 총알 피해량은 1로 설정한다.
- 웨이브를 넘어가도 남은 체력을 유지한다.

### 5.2 사격과 충돌

플레이어에서 마우스 위치를 향하는 방향을 계산하여 총알을 생성한다. 총알은 발사 시 결정된 방향으로 직선 이동하며, 첫 번째로 충돌한 좀비에게 피해를 주고 제거된다. 화면 밖으로 나간 총알도 제거한다. 좀비는 체력이 0 이하가 되면 사망 연출 후 제거되며, 해당 웨이브의 남은 적 수가 감소한다.

충돌은 객체 중심과 반지름을 사용하는 원형 판정을 기본으로 한다. 이동 중 객체를 제거할 때 반복문 오류가 발생하지 않도록 제거 예약 후 일괄 정리한다. 빠른 총알의 판정 누락 여부를 테스트하고, 필요하면 이전 위치에서 현재 위치까지의 이동 구간으로 판정한다.

### 5.3 적 행동

좀비는 맵 가장자리의 지정된 생성 지점에서 등장한다. 생성 지점은 플레이어와 일정 거리 이상 떨어진 후보 중에서 선택하여 갑작스러운 접촉 피해를 줄인다. 등장한 좀비는 매 프레임 플레이어 방향을 계산하여 추적한다. 기본 버전에서는 적끼리의 충돌과 복잡한 길찾기를 구현 범위에서 제외한다.

### 5.4 승리와 패배

- 승리: 3번째 웨이브의 적이 모두 생성되고, 살아 있는 적을 전부 처치하면 승리한다.
- 패배: 플레이어 체력이 0이 되면 즉시 게임 오버로 전환한다.
- 웨이브 완료: 해당 웨이브의 생성 예정 적이 없고 살아 있는 적도 없을 때 판정한다.
- 다음 웨이브: 완료 안내와 3초 카운트다운 후 시작한다.
- 재시작: 플레이어 체력, 적, 총알, 효과, 생성 타이머, 웨이브 정보를 초기화하고 1웨이브부터 진행한다.

| 객체 | 역할 | 초기 설계 |

| 플레이어 | 이동, 조준, 발사, 피해 처리 | 체력 5, 이동 속도 240px/초 |
| 총알 | 직선 이동, 적에게 피해 | 속도 650px/초, 피해량 1 |

| 튼튼한 좀비 | 집중 공격을 요구하는 적 | 체력 5, 속도 55px/초 |
| 효과 객체 | 발사, 피격, 사망 표현 | 정해진 시간 또는 프레임 재생 후 제거 |

## 7. 웨이브 및 콘텐츠 확장

| 웨이브 | 적 구성 | 총 적 수 | 생성 간격 | 플레이 의도 |
|---|---|---:|---|---|
| 1 | 일반 좀비 8마리 | 8 | 1.2초 | 이동, 조준, 사격과 추적 규칙 학습 |
| 2 | 일반 좀비 10마리 + 빠른 좀비 5마리 | 15 | 0.9초 | 빠른 적을 우선 처리하며 회피 |
| 3 | 일반 좀비 12마리 + 빠른 좀비 6마리 + 튼튼한 좀비 4마리 | 22 | 0.7초 | 적별 특성에 따라 공격 대상과 이동 경로 선택 |

표의 생성 간격은 적 한 마리당 등장 간격이다. 적 유형을 섞은 생성 목록을 사용하여 한 종류만 연속해서 등장하는 상황을 줄인다. 생성할 적과 현재 살아 있는 적을 구분하여 관리하고, 생성 사이에 화면의 적이 잠시 없어져도 다음 웨이브로 넘어가지 않게 한다.

콘텐츠 확장은 단순한 적 수 증가뿐 아니라 새로운 적 유형과 등장 압박의 변화로 구현한다. 실제 테스트에서는 회피 공간이 확보되는지와 권총만으로 각 웨이브를 클리어할 수 있는지 확인하여 수치를 조정한다.

## 8. 게임 진행 흐름

**시작 화면 → 1웨이브 → 웨이브 완료 안내 → 2웨이브 → 웨이브 완료 안내 → 3웨이브 → 승리 화면**

전투 중 체력이 0이 되면 패배 화면으로 이동한다. 승리·패배 화면에서는 결과와 재시작 방법을 안내한다.

| 상태 | 화면과 처리 내용 |
|---|---|
| 시작 | 제목, 조작 설명, 시작 안내 표시 |
| 게임 진행 | 입력, 이동, 사격, 적 생성, 충돌, 체력, 애니메이션 처리 |
| 웨이브 대기 | 다음 웨이브 안내와 카운트다운 표시, 전투 및 발사 중단 |
| 일시정지 | 기존 화면 위에 정지 안내 표시, 게임 시간 진행 중단 |
| 승리 | 3웨이브 클리어 결과와 재시작 안내 |
| 패배 | 게임 오버와 도달 웨이브, 재시작 안내 |

마지막 적 처치와 플레이어 사망이 같은 프레임에 발생하면 패배를 우선 처리하여 결과 판정을 일관되게 한다.

## 9. 애니메이션 및 동적 표현

| 표현 | 구현 계획 |
|---|---|
| 플레이어 이동 | 이동 시 걷기 프레임 반복, 정지 시 대기 프레임 표시 |
| 조준 방향 | 마우스 위치에 따라 캐릭터 또는 총 이미지의 방향 변경 |
| 좀비 이동 | 플레이어를 실시간 추적하며 걷기 프레임 반복 |
| 발사 | 총구 섬광을 짧게 표시하고 총알 이동 표현 |
| 피격 | 플레이어 깜빡임, 좀비 색 변화 또는 피격 프레임 표시 |
| 사망 | 사망 프레임 또는 짧은 소멸 효과 재생 |
| 웨이브 전환 | 다음 웨이브 안내와 시간 기반 카운트다운 표시 |

움직임은 프레임 수가 아닌 경과 시간(delta time)을 기준으로 계산한다. 애니메이션 역시 누적 시간에 따라 프레임을 변경하여 실행 속도에 따른 차이를 줄인다. 일시정지와 재시작 후 타이머가 비정상적으로 누적되지 않도록 초기화한다.

## 10. C++ 클래스 및 기본 구조

| 클래스 | 주요 책임 |
|---|---|
| Game | 초기화, 프레임 갱신과 그리기, 게임 상태 전환, 재시작 |
| Player | 입력에 따른 이동, 조준, 발사 간격, 체력과 무적 시간 |
| Bullet | 위치, 이동 방향, 속도, 피해량, 제거 여부 |
| Zombie | 적 유형별 능력치, 플레이어 추적, 체력, 애니메이션 |
| WaveManager | 웨이브 데이터, 생성 목록과 타이머, 완료 판정 |
| Effect | 발사·피격·사망 효과의 재생과 수명 관리 |
| ResourceManager | 이미지와 사운드 로딩 및 공유, 종료 시 정리 |

객체는 `std::vector` 등의 컨테이너로 관리한다. 일반·빠른·튼튼한 좀비는 우선 하나의 Zombie 클래스와 적 유형 데이터로 구분하여 중복 코드를 줄인다. 입력과 그리기는 glc2d 기본 프로젝트 구조에 맞춰 연결하며, 게임 규칙은 별도 클래스에서 관리한다.

한 프레임의 기본 처리 순서는 **입력 확인 → 객체 이동 및 생성 → 충돌과 피해 처리 → 제거 예약 객체 정리 → 승패·웨이브 판정 → 화면 그리기**로 한다. 승패가 결정되면 해당 프레임 이후 전투 처리를 중단한다.

## 11. 리소스 준비 계획

| 분류 | 필요한 자료 | 준비 및 적용 계획 |
|---|---|---|
| 플레이어 | 대기·걷기 이미지, 총 이미지 | 이전 대화의 캐릭터 후보 5종을 비교한 뒤 최종 선택 |
| 적 | 일반·빠른·튼튼한 좀비 이미지 | 외형과 색상으로 종류 구분, 걷기 프레임 준비 |
| 배경 | 고정 경기장 배경 1개 | 이전 대화의 배경 후보 5종을 비교한 뒤 최종 선택 |
| 전투 효과 | 총알, 총구 섬광, 피격·소멸 이미지 | 투명 배경 이미지 또는 간단한 도형 활용 |
| UI | 체력 아이콘, 제목, 상태 안내 | 글자 가독성과 배경 대비 확보 |
| 사운드 | 발사, 피격, 적 사망, 웨이브 전환, 결과 효과음 | 직접 제작 또는 사용 조건을 확인한 자료 확보 |

이전 대화에서 생성한 이미지는 후보 시안으로 취급한다. 최종 채택 여부와 실제 파일 확보는 별도로 확인하고, 게임 적용 전 프레임 크기, 중심점, 투명 배경, 이미지 여백을 정리한다. 리소스는 이미지·사운드 폴더로 구분하고, 출처·제작 방법·이용 조건을 리소스 목록 문서에 기록한다.

## 12. 구현 범위

**필수 구현:** 플레이어 1명, 권총 1종, 고정 맵 1개, 적 3종, 웨이브 3개, 이동·조준·발사, 충돌과 체력, 걷기·피격·사망 표현, 시작·일시정지·승리·패배·재시작, 기본 효과음.

**완성 후 검토할 추가 요소:** 화면 흔들림, 배경 음악, 처치 수와 클리어 시간 표시. 필수 기능 완성과 오류 수정을 우선하며, 추가 요소는 일정에 여유가 있을 때 적용한다.

**이번 과제 범위 밖:** 온라인 멀티플레이, 여러 맵, 보스전, 무기 강화, 상점, 저장·불러오기, 복잡한 길찾기. 기본 게임의 완성도를 확보하기 위해 개발 범위를 제한한다.

## 13. 주차별 개발 및 제출 계획

과제 안내의 주차는 평가 단계 기준으로 사용한다. 각 주차의 실제 제출일은 수업 공지에 따르며, 환경 구성이 완료되면 문서·리소스 작업과 함께 소스 개발을 계속 진행한다.

| 단계 | 개발 내용 | 확인 가능한 결과 | Git 태그 |
|---|---|---|---|
| 1주차 | 프로젝트·Git 환경 구성, 기획서 작성, 초기 화면과 입력 처리 시작 | 빌드 및 실행 가능한 프로젝트, 기획서, 기본 화면 출력 | f1 |
| 2주차 | 주요 이미지·사운드 확보, 클래스 구성, 배경·플레이어·적 표시 및 기본 이동 | 실제 화면에서 플레이어와 기본 적의 움직임 확인 | f2 |
| 3주차 | 조준·발사, 총알·적 충돌, 추적, 피해·무적, 1웨이브, 승패·재시작 | 한 웨이브를 처음부터 결과까지 플레이 가능 | f3 |
| 4주차 | 빠른·튼튼한 적, 2·3웨이브, 애니메이션과 효과음, 일시정지, 난이도 조정 | 3개 웨이브의 콘텐츠 차이와 동적 표현 확인 | f4 |
| 최종 | 오류 수정, 전체 플레이 검증, 리소스·문서 정리, 빌드 확인 | 시작부터 승리·패배·재시작까지 완성된 게임 | fin |

실제 작업 단위로 변경 내용을 커밋하고, 각 단계의 결과를 확인한 뒤 태그를 생성한다. 저장소에는 C++ 코드, 프로젝트 파일, 기획서, 사용 리소스와 관련 문서를 포함한다.

## 14. 과제 조건 대응 및 완료 기준

| 평가 관점 | 기획에서 대응하는 내용 |
|---|---|
| 목적·조작·규칙·범위의 명확성 | 3웨이브 생존 목표, 입력표, 체력·사격·승패 규칙, 필수 구현 범위 |
| 기본 구조와 리소스 준비 | 역할별 클래스, 이미지·사운드 목록, 기본 화면과 객체 동작 |
| 핵심 게임 로직 | 이동, 조준, 발사, 추적, 충돌, 피해, 상태 전환 |
| 스테이지·콘텐츠 확장 | 웨이브별 적 종류 추가와 생성 간격 변화 |
| 애니메이션·동적 표현 | 시간 기반 이동, 걷기, 총알, 발사·피격·사망 효과 |
| 최종 완성도 | 시작부터 종료까지 플레이 가능, 일시정지와 재시작 정상 동작 |

최종 확인 항목은 다음과 같다.

- 다른 실행 환경에서도 필요한 리소스가 정상적으로 로딩되는지 확인한다.
- 이동·조준·사격이 동시에 동작하고 화면 밖으로 플레이어가 나가지 않는지 확인한다.
- 적 유형별 체력과 속도가 구분되고 3개 웨이브가 순서대로 진행되는지 확인한다.
- 생성 대기 중인 적이 남아 있을 때 웨이브가 조기에 끝나지 않는지 확인한다.
- 무적 시간 중 중복 피해가 발생하지 않고, 총알 하나가 의도치 않게 여러 적을 맞히지 않는지 확인한다.
- 일시정지 중 이동과 타이머가 정지하고 재개 후 정상 진행되는지 확인한다.
- 승리·패배 후 재시작할 때 이전 적, 총알, 체력, 타이머가 남지 않는지 확인한다.
- 최종 게임의 주요 기능과 본 기획서의 내용이 일치하는지 확인한다.
