# 라스트 존 2주차 개발 현황

## 이번 단계의 범위

기획서와 리소스를 바탕으로 glc2d 기본 화면, 주요 클래스, 입력 및 움직임을 구현했다. 현재 버전은 전투 완성본이 아닌 2주차 이동 프로토타입이다.

## 클래스 구성

| 클래스 / 자료형 | 책임 |
|---|---|
| App | 실행 흐름, glc2d 콜백과 게임 연결, 종료 |
| GraphicEngine | glc2d 초기화, 창 생성, 라이브러리 연결, 실행 루프 |
| Game | 객체 소유, 초기화, 입력·이동·그리기 처리 연결 |
| GameInput | 키보드 입력과 마우스 위치 |
| GameTime | 프레임 경과 시간 계산 |
| GameStateController | 일시정지 상태와 전환 |
| GameRenderer | 캐릭터 출력 순서, 화면 그리기와 일시정지 표시 |
| ZombieManager | 적 생성 목록, 전체 적 갱신 |
| Player | WASD 이동, 대각선 속도 보정, 맵 내부 제한, 마우스 좌우 방향 |
| Zombie | 일반·빠른·튼튼한 좀비의 속도와 추적, 접근 시 정지 |
| SpriteAnimation | 경과 시간에 따른 걷기 4프레임, 정지 시 대기 프레임 |
| ResourceManager | 이미지·사운드 로딩 및 해제, 배경·캐릭터·조준점 그리기 |
| Vec2 / Bounds | 벡터 연산, 정규화, 이동 영역 제한 |

Player와 Zombie의 이동 계산은 glc2d 출력에서 분리하여 별도로 검증할 수 있도록 구성했다. Bullet, WaveManager, 전투용 Effect는 실제 기능을 추가하는 3·4주차에 작성한다.

## 확인 가능한 기본 동작

- 배경과 플레이어, 좀비 3종 표시.
- 실행 즉시 시작, WASD로 이동, 마우스 위치에 따라 좌우 반전. 제목과 설명문은 표시하지 않음.
- 일반 좀비 2마리, 빠른 좀비 1마리, 튼튼한 좀비 1마리가 서로 다른 속도로 추적.
- 좀비는 플레이어 기준 48픽셀 앞에서 멈춤. 접촉 피해와 적끼리의 충돌은 없음.
- 플레이어와 좀비의 걷기 애니메이션.
- Esc로 정지/재개, 진행 중 R로 위치와 애니메이션 초기화.
- 사운드 장치를 사용할 수 있으면 시작 효과음 재생. 사운드 초기화에 실패해도 게임은 실행된다. 다른 앱이 앞에 있으면 이동 갱신 중단.
- 실행 파일 위치를 기준으로 리소스 로딩. 빌드 시 이미지와 사운드 자동 복사.

## 실행 방법

1. Visual Studio 2022에서 Game/Game.sln을 연다.
2. NuGet 패키지를 복원한다. 버전은 packages.config에 명시된 glc2d 0.1.0.8과 Microsoft.DXSDK.D3DX 9.29.952.8이다. 프로젝트의 패키지 경로는 Game/packages이며, 로컬에서는 설치되어 있던 캐시를 이 경로에 복사했다.
3. 구성을 Debug / x64로 선택하고 빌드한다.
4. Ctrl+F5로 실행한다. 실행 파일은 Game/_bin/x64/Debug/Game.exe이다.
5. 별도 시작 입력 없이 바로 이동할 수 있다.

의존 라이브러리와 DLL은 NuGet 패키지에서 연결한다. packages 폴더와 빌드 결과물은 Git에 넣지 않는다. 다른 컴퓨터에서는 패키지 복원이 필요하다.

## 검증 결과와 개발 환경 참고

- Debug / x64 빌드 성공.
- 클래스 분리 후 실제 실행에서 제목·설명문 없는 즉시 시작, 이동 입력, 좀비 추적, Esc 정지·재개, R 초기화, 정상 종료를 확인했다. glc2d 창 생성에는 빈 이름 대신 일반 창 이름 Game을 사용하며 게임 화면에 제목은 출력하지 않는다.
- 실제 창에서 배경·캐릭터, Enter 시작, 적 추적, Esc 일시정지·재개를 확인했다.
- 생성 시트의 첫 번째 행에서 다음 행의 일부가 섞이던 부분을 수정했다. ResourceManager는 실제 이미지의 행별 여백을 기준으로 소스 영역을 선택한다.
- 이 PC에서는 기본 디버그 정보 생성 시 Visual Studio의 MSPDB140.DLL 버전 오류가 발생했다. 프로젝트는 LastZoneSkipPdb=true를 기본값으로 두어 실행 파일을 만들도록 했다. 이 설정에서는 실행 파일용 디버그 심볼을 만들지 않으므로 소스 중단점 디버깅이 제한된다. Visual Studio 도구 문제를 해결한 뒤 MSBuild에 /p:LastZoneSkipPdb=false를 지정하면 기본 심볼 생성을 다시 사용할 수 있다.
- 커밋과 f2 태그는 아직 생성하지 않았다.

## 수업 예제 참고

[수업 GameCraft 저장소](https://github.com/3dapi/900100_HeesungOh_GameCraft)의 ActRpg/_main.cpp, App.h, App.cpp, GraphicEngine.cpp, GamePlayer.cpp, GameTime.cpp를 확인했다.

수업 예제의 초기화·갱신·그리기 분리와 glc2d 콜백 연결 방식을 비교했다. main은 App을 생성하고 초기화·실행·종료한다. GraphicEngine이 등록한 App의 콜백은 Game::Update와 Game::Render로 전달된다. 입력·시간·상태·화면·적 관리를 각각 클래스로 분리했다. 시간 계산은 steady_clock을 사용하며 캐릭터는 값 객체로 보유한다.

## 다음 단계

3주차에는 총알 생성·이동, 사격 간격, 충돌, 체력·무적 시간, 1웨이브와 승패 처리를 구현한다. 4주차에는 3개 웨이브의 구성 차이, 전투 효과, 게임 난이도와 결과 화면을 보완한다.

현재는 상하 방향 전용 이미지가 없어 좌우 방향만 표현한다. 배경의 차량·울타리는 그림이며 이동 가능 범위는 안쪽 사각형으로 제한한다. 생성한 캐릭터 프레임의 중심점은 완전히 같지 않으므로 추후 다듬을 수 있다.

## 제출 관리

개발 결과를 확인한 뒤 실제 커밋에 f2 태그를 생성한다. 이번 작업에서는 사용자의 기존 이력을 보존하며 커밋이나 태그를 임의로 생성하지 않는다. 최종 제출 전 기획서와 실제 구현 내용을 비교한다.
